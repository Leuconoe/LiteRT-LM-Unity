# FunctionGemma-270M for Korean voice commands

Research run 2026-10-16/17. Question: can `google/functiongemma-270m-it` route the
VoiceCommand-WebServer tool contract (`assets/ToolsPrompt.txt`, 44 tools incl.
`DefaultResponse`, callsigns Alpha–Zulu) on the AR headset (kona / SM8250, CPU)?

**Answer: yes, after fine-tuning, with an app-side router.** The shipped model
(`v6e`, int8, 277 MB) on device: **eval 147/147 with 0 wrong actions**, blind
heldout4 **130/137 with 4 wrong actions**, **~0.3–0.4 s per command**, 0.9 s init.
Without fine-tuning it is unusable (8/147).

## 1. What was measured

| Set | n | What it is | Blind? |
| --- | ---: | --- | --- |
| `eval_cases.json` | 147 | every `예:` utterance in ToolsPrompt (104), filter formats (8), the prompt's STT-correction table (18), BenchmarkAudio/NoiseUnitTest sentences relabelled (17) | in-distribution by construction |
| `heldout_cases.json` | 118 | free phrasing + hard contrasts | blind for v1, then used to design v2 |
| `heldout2_cases.json` | 108 | stressed / adversarial | blind for v2, then used to design v3 |
| `heldout3_cases.json` | 123 | field / asr / reject / contrast | blind for v3, then used to design v4 |
| `heldout4_cases.json` | 137 | 72 % executable radio speech, 28 % refusals | blind for v4/v5; v6 saw its failure *classes*. 5 texts leaked into the v4 data (see §7) — "clean 132" excludes them |
| voice E2E | 504 clips | Unity AI voices (Brian/George/Sarah, generated by the DroneVRV2 session), SAPI Heami, edge-tts → ASR → FC | independent of every data version |

All sets live in `Tools/Research/FunctionGemma/FunctionGemmaBench/`. Each heldout
set was written by a separate agent that never saw the training generator; once a
set's failures guided a data change it stops counting as blind. All speech is
synthesized — ranking only.

Grading: function exact, arguments exact (`filterNames` as a set),
`DefaultResponse` by function name only. A **wrong action** is any miss that
executes something; a refusal is the safe miss.

## 2. Zero-shot, and why declarations are dropped

| Model | Declarations | eval 147 | Prompt tokens |
| --- | --- | ---: | ---: |
| FunctionGemma-270M | full | 8 | 6,856 |
| FunctionGemma-270M | compact | 3 | 4,220 |
| FunctionGemma-270M | none | — | 31 |
| gemma-3-270m-it (JSON) | full / compact | 0 / 0 | 7,421 / 2,450 |

FunctionGemma answers in English prose or passes the Korean span (`team:"알파팀"`).
Compact declarations stay at 4.2k tokens because the 26-callsign enum repeats in
19 tools. kona prefills ~600 tok/s, so declarations cost seconds per command, and
the prefix-reuse API (`Conversation::Clone`, v0.14) is not wired into our JNI.
**Every model below is trained and served with no declarations** — the tool set
lives in the weights; the prompt is the 31-token trigger sentence plus the utterance.

## 3. Training

Full fine-tune, TRL SFT, completion-only loss, bf16, 3 epochs, lr 2e-5, batch 8,
best epoch chosen by greedy generation on 300 val records. ~7–15 min per epoch on
an RTX 4090. `DefaultResponse` is trained with `{}` arguments from v2e on — the
app fills `text` with the transcript, which saves decode time on refusals.

| Data | Records | What changed |
| --- | ---: | --- |
| v1 | 12,371 | template generator (`make_dataset.py`): all tools/enums, number words, STT variants 11 %, DefaultResponse 17 %, exact-text filter vs eval |
| v2 | 12,371 | lead situational clauses (~15 %), indirect verbs |
| v3 | 14,058 | negation, state questions, near-tool unsupported, native numbers, 꺼내 vs 꺼, spacing noise; DefaultResponse 27 % |
| v4 | 12,795 | DefaultResponse back to 20 %, trailing clauses, deictic / missing-slot refusals, window on/off verbs |
| v5 | 16,776 | + 3,986 LLM paraphrases of radio speech (EXAONE-3.5-7.8B paraphraser; kept only when **two teachers** — Qwen2.5-14B and EXAONE — reproduce the seed label) |
| **v6** | **17,433** | v5 + 700 two-action refusals in the same radio style + 300 STT number codes (마커 E, 이번 프리셋, 사오기) |

## 5. The app-side router (`LiteRtLmFunctionGemmaRouter.cs`)

Ported 1:1 from `fg_common.py`; golden test 20/20 against device outputs.

1. **Schema guard** — unknown function, missing required / extra key, wrong type,
   enum miss, unknown filter name → refusal.
2. **Grounding guard** — every number must appear as digits or a number word
   (Sino, native, the contract's STT codes), `team` as its Korean reading or English
   name, `soldierName` as a substring. Stops invented slots (`드론 카메라 띄워` →
   drone 3).
3. **Clause split** — if the whole utterance is refused and it has punctuation
   clauses, run each clause; execute only if exactly one distinct executable call
   comes out ("remark, command, 빨리"); two or more stay refused, as the contract
   requires. SenseVoice `woitn` transcripts carry no punctuation, so on that path
   the split rarely fires — v5/v6 learned the style in the weights for that reason.

Effect on heldout4 clean 132 (v4e): raw 99 → router 125; on v2e, raw 81 → 116.

## 6. On the device (46a880a0, CPU, int8)

Bundle size decides latency: the prompt is 28–44 tokens, so the converter's
default prefill buckets (32/272) push most commands into the 272 bucket.

| Bundle (cache / prefill) | eval | TTFT | Prefill | Decode | ms / command |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1024 / 32·272 (default) | 147/147 | 0.45 s | 94 tok/s | 43 tok/s | 569 |
| 1024 / 64·272 | 147/147 | 0.15 s | 310 tok/s | 43 tok/s | 432 |
| **256 / 64·128** | 147/147 | **0.10 s** | **485 tok/s** | **50 tok/s** | **336** |

Same start temperature (69–70 °C) for all three. Shipped model v6e on that bundle,
router applied host-side to the device's raw outputs:

| Set | Pass | Wrong actions | ms / command incl. clause retries |
| --- | ---: | ---: | --- |

## 7b. Locked final test (heldout5, scored once)

297 utterances nobody designed data from: 5a (154, new input shapes — unpunctuated
transcripts, military register, numbers 1–16, cut-offs, code-switching) and 5b
(143, generated by Qwen2.5-14B from the tool descriptions, labelled independently).
Spoken by 7 voices — Unity AI ElevenLabs Alice/George (English-native presets; the
Korean Voice Library is not reachable through Unity AI), edge-tts SunHi/InJoon/Hyunsu
and Supertonic F1/M1 — 2,030 clips after an STT intelligibility gate. Router on.

| Model | text oracle (297) | SenseVoice w8 E2E (2,030) | wrong actions | whisper base E2E | wrong |
| --- | ---: | ---: | ---: | ---: | ---: |
| v1 | 238 | 1324 | 253 | 1225 | 276 |
| v4e | 257 | 1511 | 228 | 1326 | 261 |
| v5e | 265 | **1556** | **205** | 1336 | 279 |
| **v6e** | **266** | 1555 | 219 | 1340 | 309 |

v5e and v6e are a tie on the locked set; v6e stays the shipped model because it
keeps the contract on the in-distribution set (147/147 with zero wrong actions —
v5e executes the second half of "A하고 B"). The hard part is 5a: unpunctuated
run-on transcripts, cut-off commands and code-switching give 13–18 % wrong actions
against ~7 % on 5b, so a real recogniser's raw output is where the next gains are.

A harder second pass on the same 297 texts used open-source Korean TTS — CosyVoice3
cloning 6 native Zeroth speakers, MeloTTS-Korean at 3 speeds, Qwen3-TTS Sohee
(plain and an "urgent radio" style) — plus speed, noise (SNR 10/5 dB) and reverb
augmentation: 4,499 gate-passed clips. SenseVoice w8, router on:

| Model | pass | wrong actions |
| --- | ---: | ---: |
| v1 | 2457 (54.6 %) | 567 (12.6 %) |
| v4e | 2692 (59.8 %) | 574 (12.8 %) |
| v5e | 2762 (61.4 %) | 558 (12.4 %) |
| v6e | **2788 (62.0 %)** | 607 (13.5 %) |

Training raises the pass rate but **not** the wrong-action rate, which stays at
12–15 % for every model on these voices: the gain is refusals turning into correct
calls, while broken transcripts keep getting "repaired" into a wrong command. For a
voice UI that is the number to design around — confirm destructive commands (자폭
공격 승인, 팀 해체, 제어권 이양) or gate on ASR confidence, and train on real
recogniser output. Engine-native speed changes cost nothing (MeloTTS 0.9×/1.15× ≈
1.0×); the phase-vocoder speed augmentation halves accuracy through its own
artifacts, so its column is not a speaking-rate result.

## 8. Traps that cost time

- **Batched left-padded `generate` garbles gemma-3** (`となって…`) — score with
  `--batch-size 1`. It once turned a real 111/118 into 78/118.
- **Prompt identity.** LiteRT-LM's own tool renderer (`--tools_json_file`) differs
  from the HF chat template (598 vs 624 tokens). Ship the pre-rendered system string.
- **`pwsh -File` collapses `-PrefillLengths 64,272` into the integer 64272.** Call
  the converter directly with `@(64,128)`.
- **Eval leakage.** v4's exact-text filter predated heldout4 and let 5 of its texts
  into training. Re-run the filter against every eval set before each training.
- **Refusal share is a dial, not a fix.** 17 % under-refused, 27 % over-refused, 20 %
  plus clause-dressed refusals is where both error kinds were lowest.

## 9. Reproduce

```powershell

.\Tools\Research\FunctionGemma\Run-FunctionGemmaEval.ps1 -Train -PassThru @('--train','…\data_v6_empty\train.jsonl','--val','…\data_v6_empty\val.jsonl','--format','functiongemma','--decl-mode','none','--epochs','3','--lr','2e-5','--batch-size','8','--label','ft-functiongemma-none-v6e')
…\.venv\Scripts\python.exe …\fg_eval.py --model External\functiongemma-work\ft-functiongemma-none-v6e\merged --format functiongemma --decl-mode none --cases …\heldout4_cases.json --batch-size 1 --segment
.\Tools\Research\FunctionGemma\Convert-FunctionGemmaToLiteRtLm.ps1 -Model External\functiongemma-work\ft-functiongemma-none-v6e\merged -OutDir External\functiongemma-work\ft-functiongemma-none-v6e\litertlm-c256-p64 -CacheLength 256 -PrefillLengths @(64,128)

```
